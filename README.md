# Onely Scout

Onely Scout 是为 Onely 首期“美国社媒运营人员”招募设计的 72 小时增长作战台。它不是一个只能手动导入名单的 CRM：系统从目标画像（ICP）出发，自动生成公开检索式、采集公开职业主页、标准化、去重、基于证据评分，并将合格人选送入人工复核和个性化触达草稿队列。

> 安全声明：本仓库仅用于笔试演示。没有真实联系任何候选人，没有批量发送消息，也没有采集或推断非公开信息。产品中的发送按钮被硬锁定。

## 一分钟运行

要求：Python 3（只用于启动静态服务器）与现代浏览器。

```bash
npm run dev
```

打开 `http://localhost:4173`。无需账号、Token 或安装依赖。

运行测试：

```bash
npm test
```

重新执行公开发现（可选，需要网络）：

```bash
npm run discover -- --market "United States" --platforms "TikTok,Instagram,YouTube Shorts" --limit 10
```

脚本会把结果写入被 git 忽略的 `discovery-output/`，不会发送消息。

## 已实现功能

- **从画像出发的发现链路**：角色、市场、平台能力、creator/community/growth 强信号共同生成多来源查询。
- **120 条可核验候选池**：每条包含公开主页、联系方式来源、公开证据摘要、匹配理由、分数、等级和优先级。
- **可解释去重**：canonical URL 为第一键，标准化姓名 + 地区为第二键；测试覆盖 URL 跟踪参数和跨来源重复。
- **可解释初筛**：美国市场、岗位、TikTok/Instagram/Shorts、创作者/社群、增长数据、合作可用性六类证据加权。
- **候选人导入**：支持粘贴 CSV，导入前完成格式校验与去重预览。
- **AI 触达草稿**：只引用 1–2 条公开证据，提供退出方式；绝不自动发送。
- **跟进状态与关键统计**：优先级队列、看板、转化漏斗、来源分布、操作审计日志和 CSV 导出。
- **合规护栏**：页面持续显示安全模式；发送按钮硬锁定；不接入邮件和社媒写接口。

## 公开信息发现链路

```text
目标画像
  ↓ 角色 × 地域 × 平台 × 强信号
查询图谱
  ↓ 仅允许公开职业主页/作品集
LinkedIn public pages / Twine portfolios / Contra portfolios
  ↓ 保存 URL、来源、检索摘要、时间
字段标准化
  ↓ canonical URL + normalized name/location
去重合并
  ↓ 六维证据评分（规则透明）
P0 / P1 / P2 人工复核队列
  ↓ 人工确认事实与合作相关性
个性化草稿（不发送）
```

### 合规来源

| 来源 | 仅使用的公开字段 | 联系方式来源 | 边界 |
|---|---|---|---|
| LinkedIn 公开职业主页 | 姓名、公开 headline、经历摘要、地点、公开 URL | 公开主页中的 Message / Contact info；仅在候选人主动公开且人工批准后使用 | 不登录绕过、不抓联系人网络、不猜邮箱 |
| Twine 公开作品集 | 姓名、服务类型、地点、案例、可合作信号、公开 URL | 平台公开联系入口 | 遵守平台条款与频率限制，不自动联系 |
| Contra 公开作品集 | 公开案例、技能、服务、公开 URL | 平台公开联系入口 | 不读取登录后字段，不进行批量动作 |

生产环境应优先使用平台官方 API、获得授权的搜索服务或人工导出的公开结果；如果平台条款禁止自动采集，则仅保存搜索结果 URL，后续由人工打开复核。

### 去重逻辑

1. 清理 URL 的 `www`、query、fragment 与尾部斜线，canonical URL 相同即合并。
2. URL 不同时，标准化姓名（小写、去标点、合并空格）并与地点组合进行二次去重。
3. 跨来源疑似同一人但证据不足时不自动合并，标记 `needs_review`，避免误伤。
4. 保留来源谱系和 duplicate reason，保证每次合并可审计。

### 评分与优先级

| 维度 | 权重上限 | 证据示例 |
|---|---:|---|
| 目标岗位 | 20 | social media / community / creator marketing |
| 平台能力 | 22 | TikTok、Instagram、YouTube Shorts、Reels |
| 美国市场 | 18 | 美国地点或明确 US-market 经历 |
| creator / community | 13 | creator、influencer、UGC、community |
| 效果证据 | 9 | views、growth、engagement、revenue 或量化结果 |
| 合作可用性 | 8 | freelance、consultant、available、contract |

基础分 10；A 级 ≥ 78，B 级 58–77，C 级 < 58。P0/P1/P2 与 A/B/C 对应。AI 分数只负责排序，不能替代人工录用或联系决定。

## 72 小时拿到 100 名入驻

### 漏斗目标

| 阶段 | 数量 | 转化假设 | 动作 |
|---|---:|---:|---|
| 公开发现 | 1,500 | — | 12+ 查询簇，三类公开来源，持续去重 |
| 合格候选 | 600 | 40% | 六维证据评分 + 人工快速复核 |
| 人工批准触达 | 500 | 83% | P0 一对一个性化；P1 变量模板；全部逐条审批 |
| 有效回复 | 220 | 44% | 价值主张 + beta 稀缺性 + 低摩擦 CTA |
| 明确意向 | 150 | 68% | FAQ、收益模型、案例、15 分钟说明会 |
| 完成入驻 | 100 | 67% | 魔法链接、资料预填、5 分钟上手清单 |

该漏斗是冲刺目标而非承诺。第一天按来源和话术做 3×2 小样本验证；若回复率低于 25%，立即收紧 ICP 或调整价值主张，而不是增加发送频率。

### Day 1：发现与校验（0–24h）

- 定义 ICP：美国市场经验；TikTok/Instagram/Shorts 至少两项；有 creator/community 或粉丝关系经验；有量化结果；有 freelance/agency/consulting 可用性优先。
- 执行 12+ 查询簇并形成 1,500 条原始结果，URL 和姓名/地区双键去重。
- A 级抽样 30 人做人工事实核验，校正权重和误判；把 600 人送入复核队列。
- 产出三类价值主张：收入机会、AI 降本、参与产品共创。

### Day 2：审批与分层触达（24–48h）

- 人工逐条批准 500 人：P0 200 人引用具体案例；P1 300 人引用平台/角色组合。
- 三种 CTA：先看一页说明、参加 15 分钟集体 walkthrough、直接创建 beta 席位。
- 触达间隔、每日上限与退出机制遵循来源平台政策；本笔试不执行任何真实触达。
- 实时记录 `approved → contacted → replied → qualified`，每 4 小时按来源/话术看回复率。

### Day 3：跟进与入驻（48–72h）

- 只跟进已互动或明确许可的人；无回复最多一次礼貌跟进。
- 预填公开职业资料，候选人确认后入驻；用 5 分钟清单完成 profile、时区、平台专长和可接单状态。
- 设置 3 场 15 分钟 group onboarding，配套 FAQ 和 “first task” 示例。
- 100 人完成账号和关键资料才计为入驻，不用“点击链接”虚增转化。

## 自动化如何降低人工成本

| 工作 | 纯人工 | Onely Scout | 节省 |
|---|---:|---:|---:|
| 搜索与摘录 | 24h | 3h | 21h |
| 去重与初筛 | 12h | 1.5h | 10.5h |
| 文案初稿 | 10h | 2h | 8h |
| 人工复核与回复 | 7h | 5h | 2h |
| **合计** | **53h** | **11.5h** | **41.5h / 78%** |

节省来自机器处理重复劳动；人工时间被重新投入事实核验、判断合作意愿、回复异议与 onboarding。

```text

  index.html            # 可运行产品
  app.js                # 交互、草稿、导入、筛选、统计
  styles.css            # 响应式桌面界面
  data/candidates.json  # 120 条公开主页验证快照

  build-fixture.mjs     # 将公开搜索快照标准化为候选池
  lib.mjs               # 查询、去重、评分、字段标准化

  discover.test.mjs     # 去重、评分、查询生成测试
docs/
  DEMO_SCRIPT.md        # 3–5 分钟演示脚本
  SUBMISSION_EMAIL.md   # 提交邮件模板
```

## 设计取舍与下一步

- 当前为无需 Token 的静态 MVP；状态保存在演示数据中，刷新后复位。生产版应加数据库、权限、删除请求和审计保留策略。
- 实时发现脚本使用公开搜索 HTML 做技术演示。生产版应换成获授权的搜索 API，并为每个来源实现 rate limit 与 ToS 开关。
- 文案当前使用可解释模板；生产版可接 LLM，但必须通过结构化引用强制只使用候选记录中的公开证据。
- 不实现自动发送是有意的产品边界，而不是缺少功能：在高风险外联场景中，人工审批是必要控制点。

## 数据说明

`dist/data/candidates.json` 是 2026-10-30 的公开搜索快照，包含 120 条公开职业主页。资料可能随候选人更新或删除；评审时以链接当前内容为准。项目不主张这些人愿意加入 Onely，也没有联系任何人。
