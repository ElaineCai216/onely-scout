# 3–5 分钟演示脚本

建议录屏长度：4 分钟 10 秒。录制前运行 `npm run dev` 并打开 `http://localhost:4173`。

## 0:00–0:30｜问题与答案

“这是 Onely Scout，一个为了在 72 小时内招募 100 名美国社媒运营人员而做的增长作战台。它不是名单 CRM，而是从画像开始，完成公开发现、证据评分、人工审批、个性化触达草稿和转化管理。笔试期间发送能力被硬锁定，0 条消息真实发出。”

展示：总览页安全提示、四个 KPI、目标漏斗。

## 0:30–1:30｜从目标画像自动发现

进入“目标发现”。

“目标画像包含美国市场、Social Media / Community 角色、TikTok/Instagram/Shorts 能力，以及 creator、community、量化增长和 freelance 信号。系统把画像展开为 LinkedIn、Twine、Contra 的可审计检索式。”

点击“运行公开信息发现”，等待五个步骤完成。

“当前快照从 227 条公开结果出发，按 canonical URL 与姓名/地区去重，再以六类证据打分，留下 120 条可逐一核验的候选记录。实时脚本也随仓库提供，无需手动给它候选人名单。”

## 1:30–2:25｜可核验候选池

进入“候选池”，筛选 A 级，再搜索 `TikTok`，打开第一位候选人。

“每条记录都有公开主页、联系方式来源、匹配理由、证据摘要、评分与优先级。联系方式来源只指候选人自己公开的主页入口；我们没有猜邮箱，也不保存私人手机号。评分负责排序，不替代人工判断。”

关闭详情，点击“导入候选人”，演示两条同一 URL 的记录被识别为重复。

## 2:25–3:10｜AI 草稿而不是自动群发

从候选详情点击“生成触达草稿”，或进入“AI 触达草稿”。

“草稿只引用记录里已有的公开证据，并提供低摩擦 CTA 和退出方式。这里有三道人工审批检查。发送按钮在代码层禁用，所以原型不会误触达任何人。”

点击“换一个版本”，展示个性化证据仍保持一致。

## 3:10–3:45｜跟进与成本

进入“跟进漏斗”。

“运营看板把新发现、已复核、草稿、回复、入驻放在同一条链路。机器处理搜索、摘录、去重、初筛和草稿，人工集中在事实复核、许可、回复和 onboarding。估算把 53 小时重复劳动压到 11.5 小时，节省 41.5 小时。”

## 3:45–4:10｜72 小时打法与收尾

回到总览或进入“合规与审计”。

“Day 1 找到并校验 600 名合格人选；Day 2 人工批准 500 份分层草稿；Day 3 只跟进已互动人群，通过 15 分钟说明会和 5 分钟入驻清单完成 100 人。所有动作有审计记录，任何真实触达都必须在笔试结束后由 Onely 明确授权。”

收尾：“代码、README、候选快照、测试和发现脚本都在仓库中。谢谢。”

## 录制检查清单

- 浏览器缩放 90%–100%，窗口宽度 ≥ 1200px。
- 不打开任何候选人的外部主页，避免录入第三方内容或误触平台按钮。
- 不展示账号、Token、浏览器书签或通知。
- 最后确认录屏链接权限为“知道链接的人可查看”。
